## 1. Snapshot

| Item | Value |
|---|---|
| App | "AScrum", a simple Scrum project tool (projects, product backlog, sprints, tasks, users) |
| Framework | AngularJS **1.2.0-rc.3** (release candidate), `ngRoute` |
| UI | Bootstrap **2.1.1** LESS (vendored), angular-ui-bootstrap custom build (only `ui.bootstrap.dialog` + `transition`), jQuery (vendored) |
| Data layer | `mongolabResource`, a vendored `$resource`-like adapter for the **MongoLab REST API** |
| Backend | Express 3 + Passport 0.1 (local strategy), proxying to MongoLab over HTTPS |
| Build | Grunt 0.4 (jshint, html2js, concat, uglify, recess/LESS, copy) |
| Tests | Jasmine 1.x via Karma 0.8; 23 spec files, **133 `it` blocks** (3 spec files empty) |
| CI | Travis, Node 0.10, Firefox under xvfb, `grunt release` |
| App source size | 1,849 LOC across 40 JS files + 17 `.tpl.html` files (excluding vendor) |

**Hard external fact:** MongoLab (mLab) shut down in 2020 after it was acquired by MongoDB Atlas. The backend **cannot run as written**: `server/lib/mongo-proxy.js` and `mongo-strategy.js` both call `https://api.mongolab.com/api/1`. Any runnable target needs a replacement for the API (the planned stub).

## 3. Routes

`$locationProvider.html5Mode(true)`; `otherwise → /projectsinfo`. The server answers every unknown path with `index.html` (`server/lib/routes/appFile.js`).

`crudRouteProvider.routesFor(Resource, urlPrefix, routePrefix)` generates three routes per resource: `/<prefix>/<resource>` (List), `/<prefix>/<resource>/new` (Edit), and `/<prefix>/<resource>/:itemId` (Edit). Template is `<urlPrefix>/<resource>/<resource>-<op>.tpl.html`; controller is `<Resource><Op>Ctrl`.

| # | Path | Controller | Template | Resolves (fetched before render) | Client guard |
|---|---|---|---|---|---|
| R1 | `/projectsinfo` | ProjectsInfoListCtrl | projectsinfo/list.tpl.html | `projects = Projects.all()` | — |
| R2 | `/dashboard` | DashboardCtrl | dashboard/dashboard.tpl.html | `projects = Projects.all()`, `tasks = Tasks.all()` | — (see D4) |
| R3 | `/projects` | ProjectsViewCtrl | projects/projects-list.tpl.html | `projects = Projects.all()` | requireAuthenticatedUser |
| R4 | `/projects/:projectId/productbacklog` | ProductBacklogListCtrl | projects/productbacklog/productbacklog-list.tpl.html | `projectId`, `backlog = ProductBacklog.forProject(projectId)` | — |
| R5 | `/projects/:projectId/productbacklog/new` | ProductBacklogEditCtrl | …/productbacklog-edit.tpl.html | `projectId`, `backlogItem = new ProductBacklog({projectId})` | — |
| R6 | `/projects/:projectId/productbacklog/:itemId` | ProductBacklogEditCtrl | …/productbacklog-edit.tpl.html | `projectId`, `backlogItem = getById(itemId)` | — |
| R7 | `/projects/:projectId/sprints` | SprintsListCtrl | projects/sprints/sprints-list.tpl.html | `projectId`, `sprints = Sprints.forProject` | — |
| R8 | `/projects/:projectId/sprints/new` | SprintsEditCtrl | …/sprints-edit.tpl.html | `projectId`, `sprint = new Sprints({projectId})`, `productBacklog` | — |
| R9 | `/projects/:projectId/sprints/:itemId` | SprintsEditCtrl | …/sprints-edit.tpl.html | `projectId`, `sprint = getById`, `productBacklog` | — |
| R10 | `/projects/:projectId/sprints/:sprintId/tasks` | TasksListCtrl | projects/sprints/tasks/tasks-list.tpl.html | `tasks = Tasks.forSprint(sprintId)` | — |
| R11 | `/projects/:projectId/sprints/:sprintId/tasks/new` | TasksEditCtrl | …/tasks-edit.tpl.html | `task = new Tasks({projectId, sprintId, state:'TODO'})`, `sprintBacklogItems`, `teamMembers` | — |
| R12 | `/projects/:projectId/sprints/:sprintId/tasks/:itemId` | TasksEditCtrl | …/tasks-edit.tpl.html | `task = getById`, `sprintBacklogItems`, `teamMembers` | — |
| R13 | `/admin/projects` | ProjectsListCtrl | admin/projects/projects-list.tpl.html | `projects = all()` | requireAdminUser |
| R14 | `/admin/projects/new` | ProjectsEditCtrl | admin/projects/projects-edit.tpl.html | `project = new Projects()`, `users = Users.all()` | requireAdminUser |
| R15 | `/admin/projects/:itemId` | ProjectsEditCtrl | admin/projects/projects-edit.tpl.html | `project = getById`, `users = Users.all()` | requireAdminUser |
| R16 | `/admin/users` | UsersListCtrl | admin/users/users-list.tpl.html | `users = Users.all()` | requireAdminUser |
| R17 | `/admin/users/new` | UsersEditCtrl | admin/users/users-edit.tpl.html | `user = new Users()` | requireAdminUser |
| R18 | `/admin/users/:itemId` | UsersEditCtrl | admin/users/users-edit.tpl.html | `user = getById` | requireAdminUser |

Chained resolves: `sprintBacklogItems` is `Sprints.getById(sprintId)` → `ProductBacklog.getByIds(sprint.sprintBacklog)`. `teamMembers` is `Projects.getById(projectId)` → `Users.getByIds(project.teamMembers)`.

**Route-level semantics the port must preserve or consciously drop:**
- The view does not render until **all** resolves settle. A rejected resolve fires `$routeChangeError`, and AppCtrl turns that into a "Route change error" notification.
- Guards are resolves that return promises. When a guard fails, it pushes onto the security retry queue, which opens the login modal. On successful login the guard is retried and navigation completes. On cancel, the user is redirected to `/`.

## 6. Services & resources

### 6.1 Data layer
| Service | Notes |
|---|---|
| `mongolabResource(collection)` (vendor/mongolab) | Base URL `MONGOLAB_CONFIG.baseUrl + dbName + '/collections/' + name` = `/databases/ascrum/collections/<c>`. Static: `all`, `query(json)` (sends `?q=<JSON>`), `getById`, `getByIds` (`{_id:{$in:[{$oid}]}}`). Instance: `$id()` (reads `_id.$oid`), `$save` (POST), `$update` (PUT, with `_id` stripped), `$remove` (DELETE), `$saveOrUpdate`. Not-found shows up as a body equal to `" null "`, which becomes a `{code:'resource.notfound'}` rejection. HTTP errors **resolve to `undefined`** instead of rejecting (D10). Supports node-style success/error callbacks as well as promises. |
| `Projects` | + `forUser` (unused, returns all), `isProductOwner`, `canActAsProductOwner`, `isScrumMaster`, `canActAsScrumMaster`, `isDevTeamMember` (throws if `teamMembers` is undefined), `canActAsDevTeamMember`, `getRoles(userId)` (PO is exclusive; otherwise SM and/or DEV). |
| `ProductBacklog` | + `forProject`. |
| `Sprints` | + `forProject`. |
| `Tasks` | `statesEnum`, `forSprint` (used); `forUser` queries `{userId}` but tasks store `assignedUserId`; `forProductBacklogItem` queries `{productBacklogItem}` but tasks store `productBacklogItemId`; `forProject` is unused (D11). |
| `Users` | + `getFullName()` → `"Last First (email)"`. |

### 6.2 Cross-cutting
| Service | Behaviour |
|---|---|
| `security` | `currentUser` (`{id,email,firstName,lastName,admin}`); `requestCurrentUser()` (cached once authenticated, otherwise GET `/current-user`); `login(email,pw)` POSTs `/login` and closes the dialog on success; `logout(redirectTo)` POSTs `/logout`, clears the user, redirects; `showLogin`/`cancelLogin`; `getLoginReason`; `isAuthenticated`; `isAdmin`. It registers on the retry queue so that **any queued item opens the login dialog**. The dialog closes with success → `retryAll`; cancel → `cancelAll` + redirect to `/`. Opening a second dialog throws. |
| `securityRetryQueue` | Queue of `{reason, retry, cancel}`; `pushRetryFn(reason, fn)` returns a promise settled by retry or cancel. Reasons: `unauthenticated-client`, `unauthorized-client`, `unauthorized-server`. |
| `securityInterceptor` | Legacy `responseInterceptors`. On any **401** it queues a retry of the original request, so the user logs in and the request is replayed transparently. |
| `securityAuthorization` (provider) | `requireAuthenticatedUser`, `requireAdminUser`: route-resolve guards (see §3). |
| `breadcrumbs` | On `$routeChangeSuccess` splits the path into `{name: segment, path}`. Raw ids appear as crumb names. |
| `notifications` | Three buckets: STICKY, ROUTE_CURRENT, ROUTE_NEXT. On route change success, CURRENT is replaced by NEXT and NEXT is cleared. `getCurrent` = sticky + current. `remove`, `removeAll`. |
| `i18nNotifications` | Wraps `notifications` with message-key lookup via `localizedMessages`. |
| `localizedMessages` | `get(key, params)` interpolates `{{x}}` from the `I18N.MESSAGES` constant; a missing key renders `?key?`. 12 keys (app.js). |
| `httpRequestTracker` | `hasPendingRequests()` (drives the header spinner). |
| `crudListMethods(prefix)` | `new()` → `prefix/new`; `edit(id)` → `prefix/id`. |
| `crudEditMethods` | Controller mixin equivalent of `crudEdit`. **Used only in tests**; no controller uses it. |
| `crudRouteProvider` | Route generator, see §3. |
| `exceptionHandler` | Decorates `$exceptionHandler` to push an `error.fatal` notification. **Module not included in `app`**, and the `error.fatal` key does not exist. Dead. |

## 8. Domain model (inferred from code; there is no schema anywhere)

All documents use MongoLab's id shape: `_id: { $oid: "<24-hex>" }`. All cross-references are **plain `$oid` strings**.

| Collection | Fields |
|---|---|
| `users` | `email`, `password` (**plaintext**), `firstName`, `lastName`, `admin: bool` |
| `projects` | `name`, `desc`, `productOwner: userId`, `scrumMaster: userId`, `teamMembers: userId[]` |
| `productbacklog` | `projectId`, `name`, `desc`, `priority: number`, `estimation: number` |
| `sprints` | `projectId`, `name`, `capacity: number`, `start: string`, `end: string`, `sprintBacklog: productBacklogId[]` |
| `tasks` | `projectId`, `sprintId`, `productBacklogItemId`, `name`, `desc`, `estimation: number`, `remaining: number`, `state: TODO\|IN_DEV\|BLOCKED\|IN_TEST\|DONE`, `assignedUserId?` |

Seed data: only one admin user (`initDB.js`: `admin@abc.com` / `changeme`). There are **no fixtures** for projects, backlog, sprints, or tasks.

## 9. Backend API surface the client expects

### 9.1 Transport rules (all endpoints)
| Rule | Source | Impact on client |
|---|---|---|
| **JSON hijack prefix**: every `application/json` response body is prefixed with `)]}',\n` | server/lib/protectJSON.js | AngularJS `$http` strips it automatically; `fetch`/axios will **not**. |
| **XSRF**: every response sets cookie `XSRF-TOKEN`; any non-GET/HEAD/OPTIONS request without a matching `X-XSRF-TOKEN` header gets **403** (this includes `/login`) | server/lib/xsrf.js | AngularJS `$http` does this automatically; React code must do it explicitly. |
| Session in a signed cookie (`express.cookieSession`), Passport session | server.js | Requests need `credentials: 'same-origin'`. |
| HTML5 deep links → `index.html` | routes/appFile.js | Dev server/stub needs SPA fallback. |
| Static assets at `/static/*` | routes/static.js, index.html | Vite base path decision. |
| HTTP on 3000, HTTPS on 8433 with **committed** self-signed key | server.js, server/cert/* | — |

### 9.2 Auth endpoints
| Method | Path | Request | Response | Used by client |
|---|---|---|---|---|
| POST | `/login` | `{email, password}` | 200 `{user: {id,email,firstName,lastName,admin}}` on success; **200 `{user:null}`** on bad credentials (not 401) | yes |
| POST | `/logout` | — | 204 | yes |
| GET | `/current-user` | — | 200 `{user: {…}\|null}` | yes (app start, guards) |
| GET | `/authenticated-user` | — | 200 `{user}` or 401 | **no** |
| GET | `/admin-user` | — | 200 `{user}` or 401 (non-admin also gets 401, not 403) | **no** |

### 9.3 Data endpoints: `/databases/:db/collections/:collection[/:id]`
The server proxies these to MongoLab after applying auth middleware. `:db` is always `ascrum`.

| Method | Path | Body / query | Response | Server auth |
|---|---|---|---|---|
| GET | `/databases/ascrum/collections/{c}` | `?q=<JSON query>` (optional) | `Doc[]` | **none: reads are public, including `users` with passwords** (D7) |
| GET | `/databases/ascrum/collections/{c}/{id}` | — | `Doc`, or the body `" null "` when not found (MongoLab quirk the client relies on) | none |
| POST | `/databases/ascrum/collections/{c}` | `Doc` (no `_id`) | created `Doc` with `_id.$oid` | authenticated; **admin** if `c ∈ {users, projects}` |
| PUT | `/databases/ascrum/collections/{c}/{id}` | `Doc` with `_id` removed | updated `Doc` | same as POST |
| DELETE | `/databases/ascrum/collections/{c}/{id}` | — | deleted `Doc` | same as POST |
| any | same, unauthorized | — | **401** `{user: …}` → client retry queue → login modal | — |

Query shapes actually sent by live code:
`{}` (all) · `{projectId}` · `{sprintId}` · `{email}` · `{_id: {$in: [{$oid}, …]}}`.
Defined but unused: `{userId}`, `{productBacklogItem}`.

Collections touched: `users`, `projects`, `productbacklog`, `sprints`, `tasks`.

## 14. Observed dependency seams (facts, not a cluster plan)

- **Foundation, used by everything:** the data adapter (mongolabResource and the 5 resources), notifications/i18n, the security service with its retry queue and interceptor, crudEdit/crudButtons, crudListMethods, and the route-generation pattern.
- **Self-contained after foundation:** admin/users (+ gravatar, uniqueEmail, validateEquals); admin/projects (+ TeamMembers rules on the Projects resource).
- **Coupled chain:** projects → productbacklog → sprints (needs the product backlog) → tasks (needs sprints, backlog, projects, users).
- **Shell:** header, breadcrumbs, request spinner, login toolbar and modal, notifications outlet.
- dashboard and projectsinfo are thin screens that depend on D1–D4 decisions.
