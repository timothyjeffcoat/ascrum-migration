# Independent legacy audit: wave B screens

Scope: sprints list, sprint edit (with the sprint backlog picker), tasks list, task edit, dashboard (`/dashboard`), current projects (`/projectsinfo`), and the parts of the shell that only these screens exercise.

Method: Part 1 was written from `legacy/` alone, before anything under `spec/`, `web/`, `MIGRATION.md`, `CLAUDE.md` or `README.md` was opened, and committed on its own. Part 2 compares it with the specification and the shipped React app.

Path shorthand: `c/` = `legacy/client/src/`, `v/` = `legacy/client/vendor/`, `s/` = `legacy/server/`. Legacy Angular is 1.2.0-rc.3 (`v/angular/angular.js:2`).

## Part 1: blind reading of the legacy app

### Routes, guards and data loading

- **L1.** Sprint routes are generated by `crudRouteProvider.routesFor('Sprints', 'projects', 'projects/:projectId')`: list `/projects/:projectId/sprints`, new `/projects/:projectId/sprints/new`, edit `/projects/:projectId/sprints/:itemId` (`c/app/projects/sprints/sprints.js:13-35`, `c/common/services/crudRouteProvider.js:61-86`). `new` is registered before `:itemId`, and ngRoute takes the first match in registration order (`v/angular/angular-route.js:547`), so `/sprints/new` opens an empty form.
- **L2.** Task routes: `/projects/:projectId/sprints/:sprintId/tasks`, `.../tasks/new`, `.../tasks/:itemId` (`c/app/projects/sprints/tasks/tasks.js:19-45`).
- **L3.** Dashboard route `/dashboard` (`c/app/dashboard/dashboard.js:4`) and current projects `/projectsinfo` (`c/app/projectsinfo/projectsinfo.js:3`). Any unknown URL redirects to `/projectsinfo` (`c/app/app.js:38`).
- **L4.** None of the wave B routes has an authentication or role guard. Only `/projects` uses `requireAuthenticatedUser` (`c/app/projects/projects.js:12`); the sprint, task, dashboard and projectsinfo resolves contain only data loaders (`sprints.js:14-35`, `tasks.js:21-45`, `dashboard.js:7-16`, `projectsinfo.js:6-10`). An anonymous visitor who types the URL sees all of these screens.
- **L5.** The server allows every `GET` on every collection without login; any non-GET needs an authenticated user, and only `users` and `projects` writes additionally need an admin (`s/server.js:43-58`). Sprint, task and product-backlog writes are therefore open to any logged-in user, whatever their role on the project (or none).
- **L6.** A write rejected with 401 is queued and the login modal opens; after a successful login the request is retried (`c/common/security/interceptor.js:7-16`, `c/common/security/security.js:30-45`). Cancelling the modal clears the queue and redirects to `/`, which falls through to `/projectsinfo` (`security.js:34-36,73-76`, `app.js:38`).
- **L7.** Sprints list loads `Sprints.forProject(projectId)`, a Mongo query `{projectId}` (`sprints.js:16-18`, `c/common/resources/sprints.js:5-7`). No sort is requested, so the order is whatever the database returns (insertion order in practice). Tasks list loads `Tasks.forSprint(sprintId)` the same way (`tasks.js:22-24`, `c/common/resources/tasks.js:12-14`). Neither list checks that the project or sprint exists.
- **L8.** Sprint new/edit loads the sprint (new: `new Sprints({projectId})`; edit: `Sprints.getById(itemId)`) and the whole product backlog of the project (`sprints.js:9-11,21-35`).
- **L9.** Task new/edit loads: the task (new: `{projectId, sprintId, state: 'TODO'}`; edit: `Tasks.getById`), the product backlog items that are in this sprint's backlog (`Sprints.getById(sprintId)` then `ProductBacklog.getByIds(sprint.sprintBacklog)`), and the users who are team members of the project (`Projects.getById` then `Users.getByIds(project.teamMembers)`) (`tasks.js:5-17,27-45`). The task edit route does not check that the task belongs to the sprint or project in the URL.
- **L10.** Dashboard loads `Projects.all()` and `Tasks.all()`, i.e. every project and every task in the database, not the current user's (the TODO comments say so) (`dashboard.js:8-15`).
- **L11.** `/projectsinfo` loads `Projects.all()` but its template is only `<h3>Projects info</h3>`; the loaded projects are never shown (`c/app/projectsinfo/list.tpl.html:1`, `projectsinfo.js:6-15`).

### Error behaviour of loaders and saves

- **L12.** A failed HTTP request does not reject the resource promise: the error handler returns `undefined`, so the promise *resolves* with `undefined` (`v/mongolab/mongolab-resource.js:35-38`). Consequences: a failed list GET renders the empty-state row (`!undefined.length` is true in an Angular expression); a failed sprint GET on the edit route resolves to `undefined` and the controller then throws at `$scope.sprint.sprintBacklog` (`sprints.js:61`), leaving a broken view with only a console error.
- **L13.** A single-document GET whose body is the MongoLab "not found" marker `" null "` is rejected (`mongolab-resource.js:24-28`); a rejected resolve triggers `$routeChangeError`, which shows the red notification "Route change error" and leaves the user on the previous screen (`app.js:22,55-57`).
- **L14.** In the task routes, if the sprint GET fails the chained `sprint.sprintBacklog` throws inside `then`, which rejects and produces "Route change error" (`tasks.js:6-9`); the same for the project GET (`tasks.js:13-16`).
- **L15.** Save and remove errors on sprint and task forms are silent: `onError` sets `$scope.updateError = true` (`sprints.js:57-59`, `tasks.js:65-67`) but neither template renders `updateError` (`sprints-edit.tpl.html`, `tasks-edit.tpl.html`). The user stays on the form with no message.
- **L16.** There are no success notifications for sprint or task save or remove; the `I18N.MESSAGES` table has entries only for users, projects, login and route errors (`app.js:21-34`).
- **L17.** The `exceptionHandler` decorator that would turn uncaught exceptions into an "error.fatal" notification is defined but its module `services.exceptionHandler` is not a dependency of `app` or of any other module (`c/common/services/exceptionHandler.js:1,23-27`, `app.js:1-13`). Runtime exceptions on these screens only reach the console.

### Sprints list

- **L18.** Table `table table-bordered table-condensed table-striped table-hover` with columns Name, Start date, End date, Status, Tools (`sprints-list.tpl.html:1-10`). Start and end are printed as stored, unformatted (`:14-15`).
- **L19.** The Status column always shows the literal text `ACTIVE`, whatever the dates (`sprints-list.tpl.html:16`).
- **L20.** Clicking the Name, Start, End or Status cell opens the sprint edit form (`sprints-list.tpl.html:13-16`, `c/common/services/crud.js:76-78`). The Tools cell has a `Tasks` button (`btn btn-mini`) that opens `/projects/:projectId/sprints/:sprintId/tasks` (`:18`, `sprints.js:44-46`).
- **L21.** Empty state: one row, `colspan=5`, "No sprints defined" (`sprints-list.tpl.html:21-22`).
- **L22.** A `well` below the table contains a `New sprint` button that opens `/projects/:projectId/sprints/new` (`sprints-list.tpl.html:26-28`, `crud.js:72-74`).

### Sprint edit

- **L23.** Layout: `div.well` > `h4 Sprint` > `form[name=form][crud-edit=sprint]`; two `span6` columns with Name (text, required, `autofocus`), Capacity (number, required), Start date (text, required), End date (text, required) (`sprints-edit.tpl.html:1-17`).
- **L24.** Start and End are free-text inputs: no date format, no date picker, and no check that End is after Start (`sprints-edit.tpl.html:14,16`).
- **L25.** Capacity is an `input type=number` with `required`; Angular marks non-numeric input invalid and stores a number. Capacity is not shown anywhere else (not in the list) (`sprints-edit.tpl.html:10`).
- **L26.** Input `name` attributes are wrong but invisible to users: Capacity is `name="description"`, Start and End are both `name="name"` (`sprints-edit.tpl.html:10,14,16`). Validity is still tracked per control.
- **L27.** Save is enabled only when the form is valid **and** the sprint differs from the loaded copy; Revert changes is enabled only when it differs; Remove is visible only for a saved sprint (has an id) (`c/common/directives/crud/edit.js:74-82`, `crudButtons.js:9-11`). All three crud buttons are `type="button"`.
- **L28.** Save and Remove both navigate to `/projects/:projectId/sprints` (`sprints.js:54-56`; `onRemove` falls back to `onSave`, `edit.js:50`). Remove has no confirmation and does not delete or detach the sprint's tasks (no cascade anywhere in the client or `s/lib/mongo-proxy.js`).
- **L29.** On load the controller sets `sprint.sprintBacklog = sprint.sprintBacklog || []` before the crud-edit directive takes its pristine copy, so a sprint without a backlog field is not considered dirty (`sprints.js:61`, `edit.js:22`). A new sprint is saved with `sprintBacklog: []`.
- **L30.** Sprint backlog section: `h4 Sprint backlog`, then two `span6` tables. Left, "Currently in the sprint's backlog": Name (link), Estimation, Tools with a red `Remove` button (`btn btn-mini btn-danger`); footer row "Estimation in total" / sum / `-` (`sprints-edit.tpl.html:19-51`). Right, "Product backlog": every product backlog item of the project not already in this sprint, with Name (link), Estimation and `Add to sprint` (`btn btn-mini`) (`:53-76`, `sprints.js:88-90`).
- **L31.** The right-hand picker does not exclude items that are already in a *different* sprint; an item can be added to several sprints (`sprints.js:88-90`).
- **L32.** Order: the sprint backlog table is in the order of the `sprintBacklog` id array (most recently added last); the product backlog table is in server order (`sprints-edit.tpl.html:34,65`). Adding appends to the end; Remove splices by index (`sprints.js:72-78`).
- **L33.** The sprint backlog rows show name and estimation through a lookup built from the project's product backlog (`sprints.js:63-66`). If an id in `sprintBacklog` no longer exists in the product backlog (item deleted), the row shows a blank name and estimation, and `estimationInTotal()` throws a TypeError on every digest (`sprints.js:82-84`), so the total cell stays blank and the console fills with errors (L17).
- **L34.** An item whose estimation is missing makes the total `NaN` (`sprints.js:83`).
- **L35.** Clicking an item name (in either table) navigates to the product backlog item edit page `/projects/:projectId/productbacklog/:id`, discarding any unsaved sprint changes without warning (`sprints.js:68-70`, `sprints-edit.tpl.html:35,67`). The links have no `href`, so they are not keyboard-focusable.
- **L36.** The `Remove` and `Add to sprint` buttons have no `type` attribute, so inside the form they are submit buttons (`sprints-edit.tpl.html:39,71`). The form has no `action`, so Angular cancels the native submit (`v/angular/angular.js:14233`), but pressing **Enter** in Name, Capacity, Start or End still performs implicit submission, which fires a `click` on the form's first submit button. Result: Enter removes the **first item of the sprint backlog**; if the sprint backlog is empty, Enter adds the **first product backlog item** to the sprint.
- **L37.** Revert changes desynchronises the picker. `crud-edit` has its own child scope (`edit.js:10`); Revert assigns a fresh copy to `sprint` on that child scope (`edit.js:59-63`), while `addBacklogItem`, `removeBacklogItem`, `notSelected` and `estimationInTotal` keep operating on the controller's original object (`sprints.js:72-90`, `estimationInTotal` even uses the injected `sprint` closure). After a Revert: Add to sprint makes the item vanish from the right-hand table but not appear on the left, the total changes, and Save stays disabled; Remove changes nothing visible. Items added before the Revert are hidden from both tables. Reloading the page is the only recovery.
- **L38.** Neither sprint nor task edit has a Cancel or Back button; the only ways out are Save, Remove, the item links (L35), the navbar and the breadcrumbs, and none of them warns about unsaved changes (`crudButtons.js:8-12`, `sprints-edit.tpl.html`, `tasks-edit.tpl.html`).

### Tasks list

- **L39.** Table with columns Name (`span8`), Estimation (`span1`), Remaining (`span1`), Tools (`span2`); only the Name cell is clickable (opens task edit); the Tools cell is always empty (`tasks-list.tpl.html:1-16`).
- **L40.** Empty state: "No tasks defined for this sprint" (`colspan=4`) (`tasks-list.tpl.html:17-19`). A `well` holds `New task` (`:22-24`).
- **L41.** The screen does not show which sprint or project it belongs to, and has no link back to the sprint (only the breadcrumbs, L56).

### Task edit

- **L42.** Layout: `form[name=form][crud-edit=task]` > `div.well` > two `span6` columns. Left: Name (text, required, autofocus), Product Backlog item (select, required), Description (textarea, 8 rows, required). Right: Estimation (number, required), Remaining (number, required), State (select, required), Assigned to (select, optional) (`tasks-edit.tpl.html:1-22`). Crud buttons sit after an `hr` inside the well (`:24-25`).
- **L43.** Product Backlog item options are only the items in this sprint's backlog, labelled by name, value = item id (`tasks-edit.tpl.html:8`, `tasks.js:5-10`). If the sprint backlog is empty, the select has no options and the task can never be saved (required).
- **L44.** State options are `TODO, IN_DEV, BLOCKED, IN_TEST, DONE`, shown as the raw enum strings (`c/common/resources/tasks.js:6`, `tasks-edit.tpl.html:19`). A new task starts as `TODO` (`tasks.js:32`).
- **L45.** Assigned to lists the project's team members only (not PO or SM unless also team members), labelled `lastName firstName (email)` (`c/common/resources/users.js:5-7`, `tasks-edit.tpl.html:21`). It has no explicit empty option.
- **L46.** Angular 1.2 `ng-options` without an explicit empty option shows a blank "unknown" option while the model value is not among the options, and removes it as soon as a real option is chosen (`v/angular/angular.js:18974-18980`). Consequences: (a) a new task shows blank Product Backlog item and Assigned to; (b) once a person is assigned, the task **cannot be un-assigned** from the UI; (c) a stale value (backlog item removed from the sprint, user removed from the team) shows as blank but is **kept and re-saved** unchanged, and because the value is non-empty the `required` check passes.
- **L47.** Estimation and Remaining accept any number, including negatives and Remaining > Estimation; there is no cross-field check (`tasks-edit.tpl.html:15,17`).
- **L48.** **Save and Remove navigate to `/admin/users`**, not back to the task list (`tasks.js:62-64`, `onRemove` falls back to `onSave` per `edit.js:50`). For a non-admin this lands on an admin-guarded route and opens the login modal with the "not authorised" reason; cancelling goes to `/projectsinfo` (L6).
- **L49.** The task form has no submit button (all crud buttons are `type="button"`), and it has more than one text field, so Enter in a field does nothing (`crudButtons.js:9-11`).
- **L50.** Description has no `name`, and Assigned to reuses `name="state"` (`tasks-edit.tpl.html:10,21`); invisible to users.

### Dashboard

- **L51.** `h4 My projects`, then the `/projects` table template included verbatim (Name, Description, My Role(s), Tools with "Product backlog" and "Sprints" links), then `h4 My tasks` and a table Name / Estimation / Remaining / Tools (`dashboard.tpl.html:1-26`, `c/app/projects/projects-list.tpl.html`).
- **L52.** Dashboard project rows are broken. The shared template calls `manageBacklog(project)` and `manageSprints(project)` with the project *object* (`projects-list.tpl.html:12-17`), but `DashboardCtrl` defines them as taking an id and concatenates it into the URL (`dashboard.js:24-30`). Clicking a name, description, "Product backlog" or "Sprints" goes to `/projects/[object Object]/productbacklog` (or `/sprints`), which matches the route and shows an empty list. (On `/projects` the same template works because `ProjectsViewCtrl` takes the object, `projects.js:24-30`.)
- **L53.** The dashboard's My Role(s) column is always empty, because `DashboardCtrl` defines no `getMyRoles` (`dashboard.js:20-31`; Angular expressions swallow the undefined call).
- **L54.** "My tasks" lists every task in the database, not the user's; rows are not clickable and the Tools cell is empty; empty state "No tasks for you!" (`dashboard.tpl.html:16-24`, L10). "My projects" has no empty-state row.
- **L55.** The dashboard is reached from the brand link `AScrum` when logged in (anonymous users go to `/projectsinfo`) (`app.js:68-74`). There is no nav item for it, and nothing stops an anonymous visitor from opening `/dashboard` directly (L4).

### Shell behaviour on these screens

- **L56.** Breadcrumbs are built from the raw URL segments, so they show ids: e.g. `projects / <projectId> / sprints / <sprintId> / tasks / <taskId>`; every crumb but the last is a link to the path prefix (`c/common/services/breadcrumbs.js:9-21`, `c/app/header.tpl.html:25-33`). On these screens the `/projects/<projectId>` crumb matches no route and redirects to `/projectsinfo` (L3), and the `/projects/<projectId>/sprints/<sprintId>` crumb opens the **sprint edit form**.
- **L57.** Nav highlight follows the first breadcrumb: sprint and task screens highlight "My Projects", `/projectsinfo` highlights "Current Projects", and `/dashboard` highlights nothing (`app.js:76-78`, `header.tpl.html:5,9`).
- **L58.** A spinner appears at the right of the navbar while any HTTP request is pending (`header.tpl.html:18-21`, `c/common/services/httpRequestTracker.js:5-7`).
- **L59.** Route-scoped notifications are cleared on the next successful route change; notifications pushed "for the next route" appear after it (`c/common/services/notifications.js:18-23`). Wave B screens push none themselves (L15-L16); only "Route change error" (L13) can appear.

### Discrepancy details

**DSC-B-1: the port does not trim text input (low–medium, shipped).**
- Legacy: in AngularJS 1.2.0-rc.3 every `input` and `textarea` with `ng-model` runs `textInputType`, which trims the value unless `ng-trim="false"` is set (`v/angular/angular.js:14668-14684`; `textarea` uses the same directive, `:1654-1655`). No legacy template sets `ng-trim`. So:
  - a Name of only spaces becomes `''`, and `required` fails;
  - `"  Sprint 3 "` is stored as `"Sprint 3"`;
  - typing a trailing space does not make the form dirty.
- Port: `useCrudForm.setField` stores the raw string. `required` treats only `undefined`, `null`, `''` and `NaN` as empty (`web/src/crud/validators.ts:13-19`). The only `trim()` under `web/src` is in the number parser (`web/src/crud/useCrudForm.ts:254`).
- Reproduced on the built app (`vite build` + `vite preview` on 4873 + Node stub on 3701), logged in as `dev1`:
  - New sprint with Name `"   "`, Capacity 5, Start `"  2026-01-05  "`, End `" "`: Save was enabled, and the request was `POST …/collections/sprints {"projectId":"2000…01","name":"   ","start":"  2026-01-05  ","end":" ","sprintBacklog":[],"capacity":5}`. The sprints list then showed a third row with an empty Name and End cell.
  - New task with Name `"  "` and Description `"   \n  "`: Save was enabled, and both were stored as typed.
- Why nobody caught it: neither the inventory nor the spec mentions `ngTrim`. AC-CRUD-06/11 cover visibility and number parsing, not whitespace. Part 1 of this audit missed it too; it surfaced while reading the port's `required`.
- Scope beyond wave B (from the code, not reproduced): the same `setField` path serves the project, user, backlog-item and login forms. `type="email"` inputs are safe because the browser strips whitespace from their value (a trailing space in the login e-mail still enables Sign in, checked).
- Suggested follow-up (not done here): trim text and textarea values in one place (for example in `setField` for string fields, mirroring `ngTrim`), with a named test per form. Alternatively, record it as an accepted deviation. Either way it needs an owner decision, because the fix touches cluster 0's `useCrudForm`.

**DSC-B-2: legacy Revert broke the sprint picker; the fix is not recorded (documentation).**
- Legacy: `crudEdit` runs in its own child scope (`c/common/directives/crud/edit.js:10`). `revertChanges` assigns a fresh copy to `sprint` on that child scope (`:59-63`). `addBacklogItem`, `removeBacklogItem` and `notSelected` live on the controller scope and keep using the original object, and `estimationInTotal` uses the injected `sprint` closure (`c/app/projects/sprints/sprints.js:72-90`). After a Revert:
  - Add makes the item disappear from the right-hand table without it appearing on the left, and Save stays disabled;
  - Remove changes nothing visible;
  - items added before the Revert are hidden from both tables.
- Port: one form state. Revert restores `sprintBacklog` along with everything else, and Add after a Revert works. Checked on the built app: Add "Checkout", Revert, Add "Checkout" again → the left table lists it and Save is enabled. A unit test covers remove-then-revert (`SprintEdit.test.tsx:250`).
- Gap: the inventory (§4.3, §13), spec §6 and the deviations log do not mention this bug. Under A1, every fixed bug should be logged as an intentional deviation. One line in `spec/deviations.md` or an inventory note would close it.

**DSC-B-3: double-click Save creates duplicates, in legacy and in the port (low, not recorded).**
- Legacy: `canSave` depends only on validity and dirtiness (`edit.js:74-76`), so Save stays enabled while the POST is in flight. `$saveOrUpdate` POSTs again because the edited object never receives the new `_id` (the result is a new `Resource`; `v/mongolab/mongolab-resource.js:15-33,76-79,91-97`).
- Port: the same. `canSave` = no errors && no pending *async validators* && dirty (§4.2), and `save()` has no in-flight guard (`web/src/crud/useCrudForm.ts:149-161`).
- Reproduced on the built app: a double-click on Save on `/projects/<Webshop>/sprints/new` sent 2 POSTs, and the list showed 2 "Dup" sprints.
- This is parity, so it is not a defect of the port, but it is not listed in inventory §13 or spec §6. Recording it as "preserved" (or fixing it as a D-id) keeps the parity record complete. It applies to every "new" form, including wave A.
